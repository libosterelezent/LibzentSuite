# Generated Reference Snapshot

This folder contains a generated reference snapshot of the codebase,
derived by static AST inspection of the source tree. It provides a
browsable inventory of modules, classes, functions, methods, and plugins,
alongside signatures and docstring summaries.

## What is here

| Path | Content |
|---|---|
| `SYMBOL_INDEX.md` | summary table of every module (classes/functions/symbols + purpose) |
| `modules/<module>.md` | per-module reference: docstring, classes with public methods, public functions, heuristic side-effect tags |
| `plugins/<name>.md` | per-plugin manifest snapshot (version, description, declared settings) |

Machine-readable counterparts live in `../generated/`
(`symbol_index.json`, `plugins.json`, `module_dependencies.json`,
`coverage_report.json`, `drift_baseline.json`, `snapshot_manifest.json`).

## Relationship to the implementation

The snapshot reflects the source tree at the time it was generated and may
lag behind later changes. Handwritten topic pages provide additional project
context, and `../DISCREPANCIES.md` records known documentation/implementation
mismatches.

## Generation characteristics

The generator writes the files in this directory. The repository does not
currently apply operating-system read-only permissions to this directory;
its generated status is represented by its location and regeneration process.

## Generation and drift information

The snapshot and indexes are generated by `scripts/gen_knowledgebase.py`.
Its `--check` mode compares symbol signatures against
`../generated/drift_baseline.json` and produces a report of added, removed,
or changed symbols.

## Snapshot metadata

See `../generated/snapshot_manifest.json` for the authoritative metadata:
generation timestamp, source commit, Python version, generator identity,
schema version, and symbol counts.

## Snapshot characteristics

- Side-effect tags in `modules/*.md` (`creates_tasks`, `sleeps`,
  `publishes_event`, `db_write`, `network`) are regex heuristics over
  function bodies and can produce false positives or false negatives.
- First-doc-line "purposes" are the first lines of docstrings. Additional
  context appears in full docstrings and the handwritten topic pages.
